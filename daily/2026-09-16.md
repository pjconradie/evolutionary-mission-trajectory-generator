As documented in [[testatron/ipopt/README]] it verifies against
- pytest --unit
- pytest --regression
- pytest --integration -m "not compile"
- pytest --tutorials

However they do not all pass. Some intentionally fail. Some fails loudly like the `pytest --tutorials` will indicate fails in command outputs, while `terstron/tests` fails silently. 

Key passes are the automatic verification `testatron/ipopt/benchmarks` for IPOPT benchmarks. Ideally all `testatron/tests` and `docs/0_Users/tutorial/Tutorial_EMTG_Files` will be used as benchmarking.

Unfortunately there are configuration issues that block the verification without manual file directory or configuration manipulation.

This is documented in [[case_lookup.README]] with a presented solution.

However, we did manually verify that a configuration change for the test cases or the tutorial cases will result in more tests passing for IPOPT.

The results are here illustrated with the new configuration `testatron/ipopt/manual/coast-retest/CoastPhase_EMintercept.emtgopt` .

Using new vehicle configurations listed here `/repo/docs/0_Users/tutorial/Tutorial_EMTG_Files/Config_Files/hardware_models`.

The outputs of the configuration testcase `testatron/ipopt/manual/coast-retest/CoastPhase_EMintercept.emtg` compared to the original NASA supplied output data `testatron/tests/transcription_tests/CoastPhase_EMintercept.emtg`.

So we can assume that the solver is sufficiently robust in solving the ADSGNC systems problem.
